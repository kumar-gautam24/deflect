HLD 01What it does

Deflect answers questions about FastAPI by retrieving passages from FastAPI's documentation and asking a model to answer from those passages only — then refusing when the retrieved context isn't good enough.

The refusal is the point, and it's where the name comes from. A RAG system that always answers is easy; one that reliably says "I don't know" when the corpus doesn't cover the question is the hard part, and it's what the eval harness measures.

The system began as a modular monolith, still tagged monolith-phase1. Both shapes are kept deliberately so the split can be argued rather than assumed.

HLD 02The corpus

The corpus is the body of documents the system retrieves from — here, FastAPI's own docs. CI clones github.com/fastapi/fastapi and ingests docs/en/docs; locally that is 155 markdown files producing 2,372 chunks.

It is pinned to a commit SHA on every ingest. That's what makes eval scores comparable: a faithfulness score only means something if you know which version of the documents produced it.

Chunking

Chunks follow markdown headings rather than a fixed token window, and each chunk keeps its heading path — Tutorial > Dependencies > Sub-dependencies. That path is what lets a citation name something a human can actually navigate to, instead of "chunk 1,847".

Why the gateway has no database

The rule is a service that owns data owns its database — not every service has one. Giving the gateway a database to satisfy a pattern would invert the invariant rather than follow it. Its only state is rate-limit counters, in Redis.

HLD 04Three request paths

Everything the system does is one of three shapes: a synchronous streamed answer, or one of two long jobs that outlived the request that started them.

2 · Ingest — a job

POST /ingest returns 202 with a job id. The retrieval service writes an ingest_jobs row, then publishes to a Redis Stream; retrieval-worker consumes it, embeds ~2,372 chunks, and updates the row. Progress is readable at GET /jobs/{id} and streamed at /jobs/{id}/events.

3 · Eval run — a job, fanned out

POST /runs returns 202. Each of the 80 golden items becomes its own queued job; evals-worker answers and judges each one, and a fan-in finalises the run when the last item lands.

Why a broker exists here at all

A full eval run is roughly two hours against a free-tier quota. During development that run was destroyed twice — once by a container rebuild, once by a client timeout — losing about 45 minutes each time. Parallel workers do not make a run faster; the provider's rate limit is the ceiling. What the queue buys is retry granularity, visible progress, and survival across a restart.

Redis carries work; Postgres carries truth. Every piece of job state lives in the owning service's own database, so job status still answers when the broker is down, and there is still no shared table between services.

HLD 05Invariants

These are the rules the design will not trade. Breaking one to save effort destroys what the repository is meant to demonstrate.

InvariantWhat it rules out

HLD 06Trust model

One header, Authorization: Bearer <value>, carries three kinds of credential. A shared resolver decides which was presented and what it satisfies.

RequiredSERVICE_TOKENOPERATOR_TOKENsession · adminsession · viewer
serviceallowrefuserefuserefuse
operatorrefuseallowallowrefuse
viewerrefuseallowallowallow
sessionrefuserefuseallowallow

A service token deliberately does not satisfy operator. Machines and operators are different principals, and collapsing them would let any service trigger spend. session is a gateway-only requirement about credential kind rather than privilege level — /auth/logout revokes a session row, and a token has none to revoke.

Defence in depth, deliberately

The gateway resolves the credential and refuses obvious traffic early, then forwards the caller's original credential unchanged. Every upstream service re-resolves it with its own guard. Nothing is deleted and nothing is weakened, so a request that reaches a service another way is still checked. The rejected alternative — terminating at the gateway and passing an X-Deflect-Principal header — would rest every service's security on that header being unforgeable, which is a defect class this project has already fixed once.

The route table is the design

routes.py imports nothing but dataclasses. It is the artifact a reviewer reads to answer "what is exposed, and to whom" — replacing a posture you'd otherwise assemble by reading decorators across four services.

/metrics appears nowhere, so it is unroutable rather than protected — a later mis-wired guard cannot expose it. Each row is registered with app.add_api_route through a closure factory, so FastAPI does the path parsing and produces correct 404/405.

Streaming, not buffering

The proxy uses client.send(request, stream=True) with StreamingResponse(upstream.aiter_raw()) and a BackgroundTask(upstream.aclose). Without that background close, every proxied request leaks a pooled connection.

aiter_raw rather than aiter_bytes is deliberate: aiter_bytes would decompress the body while the relayed content-encoding header still claimed it was encoded.

Failure translation

ConditionReplyReasoning
unreachable502Distinct from an upstream that answered with an error, which is relayed as-is
timeout504A gateway that hangs turns one slow service into an exhausted edge
rate limited429With a computed Retry-After
not in table404Refused before any upstream call
repeated failure503Circuit open — fail fast

The except ordering is load-bearing: httpx.TimeoutException is a subclass of httpx.HTTPError, so the 504 branch must come first or every timeout would report as unreachable.

Circuit breaker

Five consecutive failures open an upstream's circuit for 30 seconds. Consecutive rather than cumulative: a service that fails once a day is healthy, and a running total would eventually open the circuit on one that never had a problem. A relayed 4xx does not count — the upstream answered, it just disagreed with the caller. Only the proxy's own 502/504 translations do.

The breaker's purpose is not protecting the upstream. It keeps the gateway's workers available for the upstreams that are still healthy; without it every worker blocks on the same sick service and one outage becomes total.

LLD 02The leaky bucket

A bucket of capacity units with a hole in it. Each request pours in one unit; the hole drains at the sustained rate, continuously. Refused when it would overflow — and how long until it fits is division, not a guess.

leak_per_second = rate / period          # 20/3600 = one unit per 180s
level = max(0.0, stored_level - elapsed * leak_per_second)

allowed     = level + 1 <= capacity
retry_after = (level + 1 - capacity) / leak_per_second
RouteRateBurstWhere the number lives
/ask20 / hr5Settings — an operator turns this down under load
/auth/login60 / hr10Constant — sized against the account lockout
Why a level, not GCRA

The same algorithm is often written as GCRA, tracking the next permitted arrival time in one float instead of two. It is exactly equivalent — level = (tat − now) / emission. The level form is used anyway: a bucket that drains is something a reader can picture at three in the morning, and a "theoretical arrival time" is something they have to look up. The saved float isn't worth the opacity.

The clamp at zero is load-bearing. Without max(0.0, …), an address that goes quiet for a day banks credit and returns able to send an unbounded burst.

Two implementations satisfy one protocol: InMemoryLeakyBucket and RedisLeakyBucket. The Redis one is a single Lua script — atomic without a pipeline round trip. Floats cross the Lua boundary as strings, because Redis coerces Lua numbers to integers and this algorithm is entirely fractional seconds. The Lua is a genuine hand-written reimplementation, not shared code, so an agreement test drives both through the same call sequence and asserts identical decisions.

LLD 03Which address to trust

Two functions, deliberately, because the rules genuinely differ — and a boolean flag would invite a future caller to pick the wrong one silently.

FunctionTakesCorrect when
client_addressthe leftmost XFF entryThe only trusted forwarder overwrites the header rather than relaying it — which the web BFF does.
edge_addressthe rightmost (n-from-right)You are the public edge behind a load balancer that appends the real client to whatever the caller sent.
 
# client sends:  X-Forwarded-For: 9.9.9.9
# Render yields: X-Forwarded-For: 9.9.9.9, <real client>
#                                 ^^^^^^^ attacker-controlled

Taking the leftmost entry at an edge would let any caller mint a fresh rate-limit key per request, and the limiter would be decorative. The trusted_hops >= 1 guard is also load-bearing: Python's entries[-0] is entries[0] — the spoofable end.

The counter-intuitive flag

Every service, including the gateway, runs with --forwarded-allow-ips "". uvicorn's default rewrites request.client from the leftmost XFF entry before the application runs. The gateway parses the header itself and takes the rightmost, so uvicorn must be told to leave request.client alone rather than helpfully corrupting it first.

LLD 04Sessions and passwords

Passwords are argon2id. Sessions are opaque — 32 random bytes, stored only as a SHA-256, so a dump of the database yields nothing replayable.

Postgres is the record; Redis is the working copy. On login the auth service writes the session row and sets session:<sha256> in Redis. Other services read only Redis, so none depends on auth being reachable to serve its own data — you simply cannot log in while it is down.

The TTL is the session's own lifetime

The cache entry carries the full remaining lifetime, not a short cache TTL. A shorter one is tempting as a revocation backstop, but since this is the only place a service looks, it would not bound revocation — it would quietly become the session length, logging an admin out everywhere while their cookie and database row both still called the session live. Revocation is therefore the explicit delete on logout.

Lockout

Five wrong passwords lock an account for fifteen minutes. A locked account is refused with the same 401, same body, no Retry-After as a wrong password: the lockout is reachable only for an account that exists, so any distinguishable reply would answer "is this address an admin?" in five requests. The operator learns of it from a log line carrying the user id — never the email.

Accounts are created by CLI (python -m auth.cli create-admin), never by an endpoint. This system has operators, not users.

LLD 05Job queue

Redis Streams with consumer groups. The pattern is identical for both job types.

# 1. write the row FIRST, then enqueue
job = IngestJob(status="queued", root=..., commit_sha=...)
session.add(job); await session.flush()
await queue.publish(INGEST_STREAM, job.id)

Order matters: a job that exists in Redis must always have a row behind it, or the worker has work referencing nothing. The reverse order would leave the queue holding ids that resolve to no state.

Workers acknowledge only after committing the result. A process that dies mid-job leaves its message unacknowledged, and the message returns to the group once something is consuming again — which is why the workers carry restart: unless-stopped.

The eval run fans out one job per golden item and fans back in on a count: the run finalises when the last item lands, computed from the database rather than held in memory, so a restart cannot lose the tally.

LLD 06Retrieval and the confidence gate

Retrieval is vector search over pgvector, with a reranker. The gate is what makes the system refuse.

SignalMeaning
top_scoreHow well the best chunk matches. Below min_top_score, nothing retrieved is relevant enough to answer from.
marginGap between best and second-best. A narrow margin means the retriever is guessing between passages.

Failing either threshold produces an escalation rather than an answer, and the model is never called — which is a cost control as much as a quality one. The thresholds are recorded on every trace, so an eval run knows what configuration produced its numbers instead of assuming today's.

Citations are validated against what was actually retrieved: a citation naming a chunk that was not in the context is dropped rather than shown. A model that invents a plausible source is exactly the failure the gate exists to catch.

Spend controls

Two bounds, sized against each other: 20 questions per hour per address, and 500 per day counted from the traces table. Twenty an hour over 24 hours is 480 — just under the daily ceiling, so no single address can exhaust a day's budget. Only the daily cap is a true spend bound; a botnet has many real addresses.

The index that isn't a performance index

admin_users_email_lower_idx is the only thing enforcing case-insensitive email uniqueness — the plain UNIQUE on email is case-sensitive. Without it You@x.com and you@x.com could both exist, and one of them could never log in reliably. It's declared on the model as well as in the migration, so alembic --autogenerate can't silently propose dropping it.

RealityWhere this actually stands

A design document that only describes the intended system is half a document. This is what is true as of 7 August 2026.

Working

  • End to end, verified live. POST /ask through the gateway streams SSE token by token from the FastAPI corpus.
  • 459 tests green across seven suites (plus 1 skip in evals) — gateway 74, common 114, retrieval 70, answer 55, evals 82+1 skip, auth 43, web 21.
  • The gateway branch is complete: routing, principals, streaming proxy, leaky bucket, circuit breaker, deployment.
  • Both Criticals below were found and repaired by a whole-branch review after all ten task-scoped reviews came back clean — the same pattern as sub-project C, and the reason that pass exists.

On the gateway's justification

The gateway is here for breadth — this project exists for a resume, and demonstrating one has value it wouldn't have in a product. The four-origin problem it was pointed at is real. But unlike the message broker, which earned its place after two eval runs were destroyed in practice, nothing forced this one. It was chosen, not forced, and the README says so.
